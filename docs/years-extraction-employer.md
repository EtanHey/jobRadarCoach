# Employer tenure exclusion safety

Status: source handoff; parser, SQL runtime and acceptance results are pending.

PR #512's employer-subject exclusions could discard a mixed clause containing
applicant tenure. For example, founding-group experience of 24 years followed
by applicant experience of 7 years could leave a separate 2-year specialist
requirement selected. Both specialist orderings now have null expectations.

Company-prefix, company-suffix and employer-verb exclusions share a residue
check in TypeScript, Python and generated SQL. The check removes one quantity
from the first detected tenure, then vetoes the entire result if numeric tenure
remains. Removing a whole admitted frame is insufficient: its prose tail can
include another word-number tenure. For quantity-free decade/Hebrew dual-year
markers, only the first detected marker is removed. This check also handles
employer clauses without an admitted frame. `exclusionQuantity` allows arbitrary
employer digit lengths solely for exclusions; applicant frames and catalogs
retain their existing grammar.

The existing literal-collective residue check remains intact. Optional scope,
preference masking, U04/F4-10 and scalar-ranking rules are unchanged. All 453
existing fixture values are preserved. Thirty synthetic cases add the four
reported reproducers, adjacent employer/unsupported-tenure shapes, pure
employer controls in both orders, and candidate team-management controls.
One initially authored leading-team control was narrowed to a single candidate
requirement before the fix handoff: demanding that it beat another same-rank
requirement would have changed the accepted disagreement policy.

Migration `0041_years_employer_tenure.sql` is generated by
`python3 -B scripts/generate_years_metadata.py`. Applied 0039 and 0040 are
unchanged. The new transaction contains only `CREATE OR REPLACE FUNCTION` and
the existing revoke/grant statements. It has no table alteration or row update.
Replacing an immutable function does not recompute the stored generated
`postings.list_metadata` column from 0024. Existing cached values therefore
remain until a separately authorized operator action; no backfill is included.

Both disposable SQL harnesses apply 0039, 0040 and 0041, then reapply 0041.
The PostgREST harness compares every fixture before/after reapplication and
checks that a synthetic stored value remains unchanged while direct function
evaluation returns null. Its RPC driver also compares expected quotes and
TypeScript metadata. These assertions have been authored, not executed here.

No tests/builds ran on MBP or M1. The regression-only commit was dispatched to
the existing GitHub Python/DB workflow; its last observed state was in progress,
so this handoff claims neither RED nor GREEN. Parent owns fresh pair review,
exact-SHA CI/M1 verification, migration application, cached rows and live gates.
